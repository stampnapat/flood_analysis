1ทำไมต้องใช้ Decision Treeสไลด์ 1–2

  • Decision Trees (DTs) เป็นเครื่องมือวิเคราะห์ที่นิยมที่สุดชุดหนึ่ง เคียงคู่กับ linear regression
  • จุดเด่นหลัก: model comprehensibility (ตีความโมเดลได้ง่าย)
  • คุณสมบัติ:
    • เข้าใจง่าย
    • implement ง่าย
    • ใช้งานง่าย
    • คำนวณถูก (computationally cheap)
    • รองรับทั้งงาน Classification และ Prediction
  • เครื่องมือวิเคราะห์ข้อมูลเกือบทุกตัวมี DT ให้ใช้

2Explainability & Classification Rulesสไลด์ 3

📘 นิยาม — เป้าหมายของ Decision Tree จำแนก (classify) หรือทำนาย (predict) คลาสของข้อมูลที่ยังไม่เคยเห็น (unseen data) จากชุดตัวแปรทำนาย (predictors) โดยผลลัพธ์ที่ได้คือ ชุดของกฎการจำแนก (Classification Rules)
  • ตัวอย่างเป้าหมาย: จำแนกเรคอร์ดว่า “will accept credit card offer” หรือ “will not accept”
  • ตัวอย่างกฎ: IF (Income > 92.5) AND (Education < 1.5) AND (Family <= 2.5) THEN Class = 0 (non-acceptor)
  • กฎเหล่านี้แสดงออกมาในรูป แผนภาพต้นไม้ (tree diagram) — 1 เส้นทางจากรากถึงใบ = 1 กฎ

3โครงสร้างของ Decision Treeสไลด์ 4–6

  • กิ่ง (branches) ชี้ลงด้านล่างเสมอ
  • ทุกตัวอย่างจะไปจบที่ leaf node ที่ระบุคลาสเฉพาะเจาะจงเสมอ
    • คลาสเป็นข้อมูลหมวดหมู่ (categorical) ⇒ classification trees
    • Probability estimation trees ⇒ regression trees (ตามถ้อยคำในสไลด์)
  • สร้างต้นไม้จากข้อมูลอย่างไร: ใช้แนวคิด Divide-and-conquer — นำข้อมูลแต่ละชุดย่อยมาเลือก attribute ที่ดีที่สุดเพื่อแบ่งต่อ แบบเวียนเกิด (recursive)

4ขั้นตอนการสร้างต้นไม้ (General Structure of Tree Construction)สไลด์ 7

ให้ Dt = เซตของ training records ที่เดินทางมาถึงโหนด t

📘 General Procedure — 4 ขั้น (วนซ้ำ)
  1. ตรวจ Stopping Condition — ถ้า Dt มีแต่เรคอร์ดคลาสเดียวกัน (yt) ⇒ t เป็น leaf node ป้ายกำกับ yt แล้วหยุด
  2. ถ้ามีมากกว่า 1 คลาส ⇒ ไปขั้น 2
  3. ทดสอบทุกเงื่อนไขที่เป็นไปได้ จาก attribute ที่เหลือ แล้วเลือกเงื่อนไขที่ให้ Highest Gain of Impurity Reduction (ลดความไม่บริสุทธิ์ได้มากที่สุด)
  4. Split ข้อมูลตามเงื่อนไขที่เลือก ออกเป็นชุดย่อย
  5. กลับไปขั้น 1 โดยให้แต่ละชุดย่อยเป็นโหนดปัจจุบันตัวใหม่
⭐ จุดที่มักออกสอบ ลำดับ 4 ขั้นนี้คือแกนของข้อสอบอัตนัย “จงอธิบายวิธีสร้าง decision tree” — ต้องจำให้ได้ว่า เช็กเงื่อนไขหยุดก่อน แล้วค่อยเลือก split ที่ลด impurity สูงสุด ไม่ใช่เลือก split ก่อน

6Recursive Partitioningสไลด์ 9

9Gini Indexสไลด์ 23, 25

GINI(t) = 1 − Σj [ p( j | t ) ]2
ตัวแปรความหมาย
tโหนดที่กำลังพิจารณา
p( j | t )ความถี่สัมพัทธ์ (relative frequency) ของคลาส j ที่โหนด t
jดัชนีคลาส (วนทุกคลาสในโหนด)
  • ค่าสูงสุด เมื่อทุกคลาสกระจายเท่ากัน = 1 − (1/N) เมื่อ N = จำนวนคลาส ⇒ ข้อมูลน่าสนใจน้อยที่สุด
  • ค่าต่ำสุด (= 0) เมื่อทุกเรคอร์ดเป็นคลาสเดียว ⇒ ให้สารสนเทศมากที่สุด

10Entropyสไลด์ 26–27

Entropy(t) = − Σj p( j | t ) log2 p( j | t )
  • วัด ความเป็นเนื้อเดียวกัน (homogeneity) ของโหนด
  • ค่าสูงสุด = log nc เมื่อทุกคลาสกระจายเท่ากัน ⇒ ได้สารสนเทศน้อยที่สุด (2 คลาส ⇒ สูงสุด = 1)
  • ค่าต่ำสุด = 0.0 เมื่อทุกเรคอร์ดเป็นคลาสเดียว ⇒ ได้สารสนเทศมากที่สุด
  • วิธีคำนวณคล้ายกับ GINI ทุกประการ

C1C2P(C1)P(C2)การแทนค่าEntropy

⚠️ จุดที่นักศึกษามักสับสน
  • Gini กับ Entropy คนละสเกล — 2 คลาสที่ 50/50:
    • Gini = 0.5 แต่ Entropy = 1.0
    • อย่าเอาค่าข้ามสูตรมาเทียบกันตรง ๆ
  • ทั้งคู่ “ยิ่งมากยิ่งแย่” (impurity สูง) แต่ Information Gain ยิ่งมากยิ่งดี เพราะเป็นค่า ลดลง ของ impurity
  • 0 log 0 กำหนดให้เป็น 0 (ไม่ใช่ค่าที่นิยามไม่ได้) ตามที่สไลด์แสดง

12.1 ตัวแปรหมวดหมู่ (Categorical)

วิธีลักษณะตัวอย่าง CarType
Multi-way splitใช้จำนวน partition เท่ากับจำนวนค่าที่แตกต่างกันFamily | Sports | Luxury (3 กิ่ง)
Binary splitแบ่งค่าออกเป็น 2 เซตย่อย ต้องหา optimal partitioning{Sports, Luxury} vs {Family} หรือ {Family, Luxury} vs {Sports}
  • ต้องตรวจ ทุกวิธีที่แบ่งหมวดได้ เช่น หมวด A, B, C แบ่งได้ 3 แบบ: {A}+{B,C}
  • {B}+{A,C}
  • {C}+{A,B}
  • ถ้ามีหมวดมาก จำนวน split จะ มหาศาล
  • บางเครื่องมือรองรับเฉพาะตัวแปรหมวดหมู่แบบ binary เท่านั้น

13Information Gainสไลด์ 33–35

Impurity รวมของการ split คือ ค่าเฉลี่ยถ่วงน้ำหนัก (weighted average) ของ impurity ในแต่ละโหนดลูก — แล้วเทียบ measure นี้ข้ามทุก split ในทุกตัวแปร เลือกอันที่ลด impurity มากที่สุด

GAINsplit = Entropy(p) − Σi=1..k ( ni / n ) × Entropy(i)
ตัวแปรความหมาย
pParent node ที่ถูกแบ่งออกเป็น k partitions
kจำนวน partition (โหนดลูก)
niจำนวนเรคอร์ดใน partition ที่ i
nจำนวนเรคอร์ดทั้งหมดที่ parent node
  • GAIN = Entropy(Parent) − Entropy(Children แบบถ่วงน้ำหนัก)
  • วัด ปริมาณ Entropy ที่ลดลง เพราะการ split นั้น
  • เลือก split ที่ให้ GAIN สูงสุด
  • ใช้ใน C4.5
  • วิธีเลือก split (สไลด์ 35): parent มี impurity = M0
  • ถ้าแบ่งด้วย A ได้ลูก N1, N2 → impurity รวม = M12
  • ถ้าแบ่งด้วย B ได้ N3, N4 → M34
  • เทียบ M0 − M12 กับ M0 − M34 แล้วเลือกอันที่มากกว่า

15Splitting Based on GINIสไลด์ 40–41

GINIsplit = Σi=1..k ( ni / n ) × GINI(i)

โดย ni = จำนวนเรคอร์ดที่ลูกตัวที่ i และ n = จำนวนเรคอร์ดที่โหนด p · ใช้ใน CART, SLIQ, SPRINT

ตัวอย่าง Binary Attribute สไลด์ 41

โหนดC1C2จำนวนGini
Parent66120.500
N1 (B = Yes)5271 − (5/7)2 − (2/7)2 = 0.194
N2 (B = No)1451 − (1/5)2 − (4/5)2 = 0.528
Gini(Children) = (7/12)(0.194) + (5/12)(0.528) = 0.333  ⇒  Gain = 0.5 − 0.333 = 0.167

ผลของการถ่วงน้ำหนัก (Effect of Weighing partitions): อัลกอริทึมจะ “เล็ง” partition ที่ ใหญ่และบริสุทธิ์ (Larger and Purer) เพราะโหนดที่มีเรคอร์ดมากจะมีน้ำหนักในสูตรมากตามไปด้วย

หมายเหตุ: สไลด์ 41 เขียน Gini(N1) = 0.194 คู่กับข้อความ Gini=0.333 ในตารางกลาง ซึ่งคือค่า Gini ของลูกแบบถ่วงน้ำหนักรวม

22Pre-Pruning (Early Stopping)สไลด์ 57–61

📘 นิยาม หยุดอัลกอริทึม ก่อน ที่ต้นไม้จะโตเต็มที่ (fully-grown tree)

เงื่อนไขการหยุดของโหนดที่ใช้กันทั่วไป:

  • หยุดถ้าทุก instance เป็นคลาสเดียวกัน
  • หยุดถ้าค่า attribute ทุกตัวเหมือนกันหมด

แต่ไม่จำเป็นต้องรอให้ทุกตัวเป็นคลาสเดียวกัน — สามารถตั้ง threshold ของค่า impurity (เช่น Entropy) ที่โหนดปัจจุบัน ถ้าต่ำกว่าค่า threshold ก็หยุดสร้างโหนดลูกได้เลย

ตัวอย่างเงื่อนไขเพิ่มเติม:

  • หยุดถ้าจำนวน instance น้อยกว่า threshold ที่ผู้ใช้กำหนด
  • หยุดถ้าการกระจายคลาสของ instance เป็นอิสระจาก feature ที่มีอยู่ (เช่น ทดสอบด้วย χ²)

23Post-Pruningสไลด์ 62

📘 นิยาม ปล่อยให้ต้นไม้โต จนเต็มที่ก่อน แล้วจึงตัดโหนดหรือ subtree ทิ้งเพื่อให้ต้นไม้เล็กลง
  • แก้ปัญหาต้นไม้ที่เฉพาะเจาะจงเกินไปจนเกิด Overfitting
  • ตัดแต่งโหนดแบบ bottom-up (จากใบขึ้นไปหาราก)
  • ตัวอย่างวิธีตัด:
    • แทนที่ทั้ง subtree ด้วย leaf node เดียว โดยมีเงื่อนไขว่าค่า impurity (เช่น Entropy) ของโหนดใหม่ยังไม่เกินค่า threshold
    • ตัดกิ่งที่จะทำผลงานได้ไม่ดีกับข้อมูลในอนาคต โดยใช้ Validation Dataset ตัดสิน
⚠️ Pre vs Post — ที่มักสับสน
  • Pre-pruning = หยุดก่อนโต (เร็วกว่า แต่เสี่ยงหยุดเร็วเกินไปจนพลาด split ที่ดีในชั้นลึก)
  • Post-pruning = ปล่อยโตเต็มแล้วค่อยตัดจากใบขึ้นมา (ใช้เวลามากกว่า แต่เห็นภาพรวมทั้งต้นก่อนตัดสินใจ)

  • Cross-validation ไม่ได้ “เพิ่มข้อมูล” — มันแค่หมุนเวียนว่าส่วนไหนเป็น test เพื่อให้ทุกเรคอร์ดได้ถูกใช้ทดสอบ 1 ครั้ง
  • และต้องได้โมเดล K ตัว จึงต้องเทรน K รอบ ไม่ใช่รอบเดียว

30สูตรสำคัญ

1. Gini Index
GINI(t) = 1 − Σj [ p( j | t ) ]2
2. Entropy
Entropy(t) = − Σj p( j | t ) log2 p( j | t )
3. Information Gain
GAINsplit = Entropy(p) − Σi=1..k ( ni / n ) × Entropy(i)
4. GINI ของการ split
GINIsplit = Σi=1..k ( ni / n ) × GINI(i)
5. Gain Ratio
Gain Ratio = Information Gain / Split Info   โดย   Split Info = − Σj=1..m p( j ) log( p( j ) )
ใช้สูตรไหน เมื่อไรคำอธิบาย
วัด impurity ของ โหนดเดียวGini หรือ Entropy
ตัดสินว่า split ไหนดีกว่าInformation Gain (สาย Entropy) หรือ GINIsplit (สาย Gini) — เลือกค่าที่ลด impurity มากสุด
เมื่อ attribute มี ค่าที่เป็นไปได้จำนวนมากGain Ratio เพื่อหักล้างความลำเอียง

⭐ 1. ขั้นตอนการสร้างต้นไม้ 4 ขั้น เช็ก stopping condition → ทดสอบทุกเงื่อนไขแล้วเลือกอันที่ลด impurity สูงสุด → split → วนซ้ำ (หัวข้อ 4)
⭐ 2. คำนวณ Gini / Entropy จากตารางนับคลาส

  • 0.94 − 0.69 = 0.247

⭐ 5. Gain Ratio และปัญหา Student ID
  • Gain ลำเอียงเข้าหา attribute ที่มีกิ่งเยอะ
  • Split Info = − Σ p(j) log p(j) โตตามจำนวนกิ่ง (สูงสุด log m)
  • หารแล้วได้ค่ายุติธรรม (หัวข้อ 17)
⭐ 6. จับคู่อัลกอริทึมกับเกณฑ์
  • ID3, C4.5 ↔ Entropy/Information Gain (C4.5 ใช้ GAIN)
  • CART, SLIQ, SPRINT ↔ Gini
  • Scalable = SLIQ, SPRINT
  • Entropy กับ Gini ให้ต้นไม้คล้ายกัน
⭐ 7. Underfitting vs Overfitting บนกราฟ error
  • Underfitting = error สูงทั้ง 2 เส้น
  • Overfitting = test error เพิ่มขณะ training error ลด
  • แกน X คือจำนวนโหนด (หัวข้อ 21)
⭐ 8. Pre-pruning vs Post-pruning
  • หยุดก่อนโต vs ตัดหลังโต (bottom-up)
  • จำชื่อเกณฑ์ exception threshold / classification threshold และบทบาทของ Validation Dataset
⭐ 9. Multi-way vs Binary split และการแบ่งตัวแปรต่อเนื่อง
  • หมวด A,B,C แบ่ง binary ได้ 3 แบบ
  • ตัวแปรต่อเนื่องใช้ discretization หรือ binary decision (A < v) ซึ่งกินเวลาคำนวณมากกว่า
⭐ 10. ข้อดี–ข้อเสียของ Decision Tree
  • ข้อเสียที่สไลด์เน้น 3 ข้อ: ต้นไม้ใหญ่
  • greedy จึงอาจไม่ได้ต้นไม้ที่ดีที่สุด
  • noise ⇒ overfitting
⭐ 11. วิธีประเมินโมเดล 4 แบบ
  • Hold-out (ข้อมูลเยอะ)
  • Random sub-sampling (ทำซ้ำแล้วเฉลี่ย)
  • K-fold CV (เทรน K รอบ)
  • Leave-one-out (K = N ใช้เมื่อข้อมูลน้อย)
⭐ 12. การไล่ต้นไม้กับข้อมูลใหม่
  • เริ่มที่ราก ไล่ตามค่าของ attribute จนถึงใบ
  • Refund=No, Married, 80K ⇒ Cheat = No (ไม่ได้ใช้ TaxInc เลย)

33สรุปท้ายบท

✅ สรุปทั้งบทใน 12 บรรทัด
  • Decision Tree = โมเดลจำแนก/ทำนายที่ให้ผลลัพธ์เป็น ชุดกฎ IF-THEN ที่มนุษย์อ่านเข้าใจ
  • โครงสร้าง: root → interior nodes → leaf nodes · ทุกตัวอย่างจบที่ใบเสมอ
  • สร้างด้วย divide-and-conquer แบบ recursive: เช็กเงื่อนไขหยุด → เลือก split ที่ลด impurity สูงสุด → แบ่ง → วนซ้ำ
  • Impurity วัดด้วย Gini หรือ Entropy — สูงสุดเมื่อคลาสกระจายเท่ากัน ต่ำสุด (0) เมื่อบริสุทธิ์
  • คุณภาพของ split = impurity ของลูก ถ่วงน้ำหนักด้วยจำนวนเรคอร์ด เทียบกับ parent
  • Information Gain (C4.5) และ GINIsplit (CART) เลือก split ที่ลด impurity ได้มากที่สุด
  • Information Gain ลำเอียงเข้าหา attribute ที่มีกิ่งเยอะ ⇒ แก้ด้วย Gain Ratio (หารด้วย Split Info)
  • เงื่อนไขทดสอบมีทั้งแบบ nominal/continuous และ 2-way/multi-way
  • ตัวแปรต่อเนื่องต้องหาจุดตัดที่ดีที่สุด
  • ปล่อยให้ต้นไม้โตจนบริสุทธิ์ 100% = overfitting — จำ noise จนทำนายข้อมูลใหม่ไม่ได้
  • แก้ด้วย pre-pruning (หยุดก่อนโตด้วย threshold) หรือ post-pruning (ตัดกิ่งจากล่างขึ้นบน ใช้ validation set)
  • ข้อดี:
    • เร็ว ตีความง่าย เลือกตัวแปรให้อัตโนมัติ ไม่ต้อง scale feature
    • ข้อเสีย: ต้นไม้ใหญ่
    • greedy
    • ไวต่อ noise
  • ขยายผลด้วย Random Forest (หลายต้น + majority vote) และประเมินผลด้วย hold-out / random sub-sampling / cross-validation / leave-one-out
